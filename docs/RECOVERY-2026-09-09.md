# Incident 2026-09-09: /tmp wipe took the serving stack down

## What happened

- The jobe host rebooted on **2026-09-06 18:44** (uptime -s).
- The serving container `qwen28tp4m` had its kernel artifacts (`/tmp/xpu_artifacts/*.so`)
  and patch scripts (`/tmp/qwen28/patches/*.py`) bind-mounted **from /tmp**.
- `/tmp` is ephemeral: the reboot wiped it. The container then exited (255) and
  could not restart; the box served nothing from Sep 6 to Sep 9.

## What was recovered (and how)

| Asset | Where found | Now durable at |
|---|---|---|
| `_xpu_C.abi3.so`, `libgrouped_gemm_xe_2.so`, `libgrouped_gemm_xe_default.so` | `vxkbuild` container FS (`docker cp vxkbuild:/vxk/build/...`) | `jobe:~/xpu_artifacts/` |
| `fix_smallm_placement.py` | `vxkbuild:/vxk/` | `jobe:~/qwen28/patches/` + this repo |
| Kernel source diff (395 lines, 8 files) | `vxkbuild:/vxk` git worktree (`git diff` @ `1796aa8`) | `kernel/vxk_worktree.patch` |
| Build script | `vxkbuild:/vxk/jobe_xpuc_fg.sh` | `build/jobe_xpuc_fg.sh` |
| `_xpu_C` build log | `vxkbuild:/tmp/build__C.log` | `build/build__C.log` |
| Patched vLLM files (post-patch ground truth) | dead `qwen28tp4m` writable layer (`docker export qwen28tp4m \| tar -x`) | `patched-sources/` |
| The 5 vLLM-side patch diffs | regenerated: patched files (above) vs upstream raw @ `ac7509e2b` | `patches/diffs/*.patch` |

## What was lost, and what replaced it

- `patch_fp8_stack.py` and `patch_vllm_worker_affinity.py` (and `apply_smallm_patch.py`)
  were `/tmp` bind-mount sources — gone with the reboot. Their **effect** is fully
  recovered: the patched vLLM files and exact diffs above reproduce the deployed
  state bit-for-bit, and `start.sh` bind-mounts those files directly, eliminating
  the patch-at-startup mechanism (and its idempotency crash-loop failure mode)
  entirely.
- If the original scripts are ever needed, they exist in the EdgeQuant agent's
  skill store (`qwen-27b-optimized-stack` lineage).

## Structural fixes so this can't recur

1. All runtime inputs now mount from durable paths: `~/xpu_artifacts/`,
   `~/qwen28/`, and this repo's `patched-sources/`. Nothing mounts from `/tmp`.
2. `start.sh` preflights artifact existence before `docker rm -f` — a missing
   artifact aborts cleanly instead of killing a working container first.
3. The kernel diff is committed here, so the artifacts are rebuildable from
   source even if every copy on jobe is lost (`build/build-kernel.sh`).
